# 发布说明

写给人看，不写给机器看。

## 结构

1. **一句话概括**：这个版本最重要的变化，不超过 25 字。
2. **分类列表**：`新增` / `修复` / `调整` / `移除`，只保留有内容的那几个。
3. **已知问题**：有就写，没有就删掉这一节。

## 措辞

- 写「用户能感觉到什么」，不写「改了哪个类」。
- 每条先一行结论，需要解释才写第二句。
- 不写 commit hash、不写 issue 号、不写内部代号。
- 破坏性变更单独标出来，放在最前面。

## 收尾

打 tag 之前确认版本号与内容一致：有新增功能走 minor，只有修复走 patch。
